# Marketing Strategy

## Principle

Четыре способности — не изобретённый список, перенос из независимо исследованной Capability Map профессии директора по маркетингу. Не строй заново то, что уже спроектировано — реализуй.

## Метод

### 1. Intake — с чем работаем

Полный разбор или узкий вопрос по одной способности? Не предполагай полный, если спросили об одном. Зафиксируй слова владельца дословно до анализа (Входной гейт задачи, `CLAUDE.md`).

### 2. Outcome Gate — на входе

Подключи скилл `outcome-gate`, шаг 1: какой конкретный разрыв владельца должен закрыть этот разбор — не «будет позиционирование», а «сейчас непонятно X».

### 3. Diagnosis — это вообще маркетинг?

Прежде чем разбирать способность — проверь: узкое место реально в маркетинге, или в продукте/цене/операционке? Если нет — скажи прямо, остановись и назови настоящую причину.

### 4. Capability Selection — какие способности нужны сейчас

Не запускай все подряд. Responsibility-матрица (Input/Constraint для каждой):

| Способность | Input | Constraint (проверяется, не читается как вход) |
|---|---|---|
| Audience Research | ICP, если есть | — |
| Positioning & Category Definition | Audience Profile, конкурентная карта | Brand (если существует) |
| Messaging & Persuasion Design | Positioning Statement | Brand (если существует) |
| Brand Strategy & Equity Management | Positioning Statement, Messaging Framework | Personal Brand (если первое лицо — часть предложения) |

Если актив устарел или отсутствует — способность, которая его создаёт/обновляет, входит в очередь. Граф ацикличен: Audience → Positioning → Messaging → Brand.

**Личный бренд — не пятая способность в этом графе.** Когда бизнес держится на первом лице, работа над личным брендом идёт через отдельный скилл `personal-brand`, а её результат становится входом для линзы Brand as Person внутри Brand Strategy (см. `references/brand-strategy.md`, «Brand as Person — стык с личным брендом»). Не пересобирай личный бренд заново внутри этого скилла.

### 5. Сбор данных — по способности, с проверенной методологией

Не изобретай метод на ходу — по каждой способности есть верифицированная методология:

- **Audience Research** — `references/audience-research.md` (Moesta Switch Interview / Ulwick ODI / Bourgoin Trigger Technique — выбирай по задаче: качественный причинный инсайт vs количественная приоритизация vs быстрая кампания).
- **Positioning & Category Definition** — `references/positioning.md` (Dunford 10 шагов — дефолт; Category Design — только если реально новая категория, не по умолчанию).
- **Messaging & Persuasion Design** — `references/messaging-persuasion.md` (Reeves USP как проверка силы уже найденного Positioning-отличия + Cialdini, один принцип на бриф, не все семь). Скилл `conversion-method` дополняет для разового конверсионного текста, не заменяет эту методологию.
- **Brand Strategy & Equity Management** — `references/brand-strategy.md` (Aaker Identity Model как основной метод + обязательный корректирующий чек Sharp/Ehrenberg-Bass перед финализацией).
- **Бриф на упаковку первички (застройщик, ДДУ)** — `references/developer-listing-brief.md`. Специализация Трёхчастного брифа (Messaging) под конкретный сценарий, не отдельная способность — используй, когда объект от застройщика, не для вторички.

Данные о самом бизнесе владельца — спрашивай напрямую, не выдумывай. Если решение крупное — узкий бриф агенту-специалисту с критерием достаточности, зафиксированным до вызова.

**Разбор конкурентов и рынка — через субагентов, не инлайн.** Для конкурентной карты (вход Positioning) и рыночного контекста дальше используй `Agent`-инструмент, а не веди исследование сам в этом же контексте: `competitor-researcher` (сырые профили по именам/URL, метод `competitive-brief`) и `market-researcher` (находки из Telegram, метод `telegram-research`). Несколько конкурентов — можно параллельно, каждому субагенту свой узкий список. Субагент возвращает только сырые находки с источниками — синтез (opportunities/threats/выводы для позиционирования) остаётся за тобой, у субагента нет контекста твоего бизнеса.

### 6. GTM/Лидогенерация — не отдельный шаг

Если вопрос владельца про лидогенерацию/каналы — это не пятая способность, а применение уже собранного (Audience+Positioning+Brand) к вопросу «какой канал доверия». Не изобретай отдельную методологию.

### 7. Validate — перед выдачей

- ЗНАЮ/ПРЕДПОЛАГАЮ на каждом выводе.
- Outcome vs Output — реально меняет что-то для владельца, или checkpoint?
- Constraint-проверка — не противоречит Brand (если есть), не противоречит Personal Brand (если первое лицо — часть предложения), не противоречит исходному разрыву из шага 2.
- Approval Gate — стратегические решения (Positioning, Brand, смена сегмента) идут владельцу с разложенными вариантами и аргументами и ждут явного «да». Не внедряется постфактум ни при каких обстоятельствах.

### 8. Outcome Gate — перед сохранением

Подключи скилл `outcome-gate`, шаг 2. Сверь с разрывом из шага 2 этого скилла.

### 9. Сохрани

`knowledge/businesses/<слаг>.md` — обновляется, не переписывается с нуля. Это внутренний рабочий файл — со всеми пометками ЗНАЮ/ПРЕДПОЛАГАЮ, источниками, ходом разбора.

### 10. Постановка задачи специалисту — после утверждения владельцем, не раньше

Стратегия и её утверждение владельцем (шаг 7, Approval Gate) идут первыми. Только после явного «да» — задача уходит специалисту-исполнителю (Авитологу, копирайтеру, трафик-менеджеру и т.д.), не раньше и не в обход.

Три канала, в этом порядке предпочтения, и обязательное отдельное подтверждение перед каждой отправкой — см. `.claude/rules/delegation-protocol.md` этого агента за полным протоколом. Какой специалист вообще существует на сегодня — `references/team-microdirections.md`, не додумывать по памяти.

### 11. Приёмка работы специалиста — не автоматическая

Когда специалист возвращает результат (карточка, текст, посадочная страница, разбор конкурентов) — CMO не подписывает его по факту получения. Прогоняет через собственные критерии приёмки (скиллы `humanizer`, `cro-auditor`, `lead-magnets`, `competitive-brief`, `customer-journey-mapping` — по тому, что именно оценивается) и либо принимает с явным обоснованием, либо возвращает на доработку с конкретным указанием, что не так.

## Integration-происхождение

Операционный цикл и Responsibility-матрица — перенос без изменения логики из независимо исследованной Capability Map профессии директора по маркетингу (2026-07-26).

Методология трёх из четырёх способностей (Audience Research, Positioning, Brand Strategy — `references/`) — исследована и верифицирована 2026-08-19, по прямому требованию владельца («директор — это сильные знания»). Четвёртая (Messaging) — частично закрыта существующим скиллом `conversion-method`, не дублировалась.

Формат вывода (текст, не таблицы по умолчанию) — решение владельца, `grilling` 2026-08-19.

Роль расширена до топ-уровня (CMO: стратегия/воронка/позиционирование/смыслы, личный бренд как прямая зона ответственности, обязательная приёмка работы специалистов) и переведена на канон `.claude/rules/*.md` — `grilling` 2026-09-09.
