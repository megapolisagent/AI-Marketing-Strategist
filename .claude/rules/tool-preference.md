# Приоритет инструментов веб-доступа

> Какой инструмент брать по умолчанию для поиска и чтения веб-страниц.

## Правило

Для любого поиска в вебе и получения содержимого страницы — по умолчанию **Exa** (`mcp__exa__web_search_exa` для поиска, `mcp__exa__web_fetch_exa` для получения страницы), не встроенные `WebSearch`/`WebFetch`.

`WebSearch`/`WebFetch` — только когда:
- Exa вернула пусто или явную ошибку на этом конкретном запросе;
- конкретный скилл прямо предписывает другой инструмент для этого шага (пример: `.claude/skills/telegram-research/SKILL.md` требует `curl` через `Bash`, не Exa и не WebFetch, для чтения самих постов — это осознанное исключение, не отмена общего правила).

## Зачем

Проверено напрямую (владелица, 2026-09-14, `.claude/skills/competitive-brief/SKILL.md`, Research Sources): на официальном сайте застройщика (`alia.moscow/flats/`) `WebFetch` и ручные попытки давали пусто или домыслы на JS-рендеренных страницах — Exa отдала полную страницу с ценами. Тот же класс сайтов (каталоги объектов, JS-рендер) встречается в этой нише постоянно. `WebSearch` и `WebFetch` — общий инструмент харнесса без специализации под такие страницы; Exa в этом проекте уже подключена именно для этого и подтверждена рабочей.

## Как применять

До вызова `WebSearch`/`WebFetch` — спросить себя: пробовал ли Exa на этом запросе? Если нет — сначала Exa. Это касается директора и обоих поисковых субагентов (`competitor-researcher`, `market-researcher`) одинаково — предпочтение не зависит от того, кто делает запрос.
