# Приоритет инструментов веб-доступа

> Какой инструмент брать по умолчанию для поиска и чтения веб-страниц.

## Правило

Для любого поиска в вебе и получения содержимого страницы — по умолчанию **Exa** (`mcp__exa__web_search_exa` для поиска, `mcp__exa__web_fetch_exa` для получения страницы), не встроенные `WebSearch`/`WebFetch`. Каталоги объектов застройщиков в этой нише почти всегда JS-рендер — `WebSearch`/`WebFetch` на части из них отдают пусто или домысел, Exa рендерит их корректно.

`WebSearch`/`WebFetch` — только когда:
- Exa вернула пусто или явную ошибку на этом конкретном запросе;
- конкретный скилл прямо предписывает другой инструмент для этого шага (пример: `.claude/skills/telegram-research/SKILL.md` требует `curl` через `Bash`, не Exa и не WebFetch, для чтения самих постов — это осознанное исключение, не отмена общего правила).

## Как применять

До вызова `WebSearch`/`WebFetch` — спросить себя: пробовал ли Exa на этом запросе? Если нет — сначала Exa. Это касается директора и обоих поисковых субагентов (`competitor-researcher`, `market-researcher`) одинаково — предпочтение не зависит от того, кто делает запрос.

## Проверка цены/юнита перед публикацией карточки — Firecrawl, не Exa

Exa (`web_fetch_exa`) читает страницу как линеаризованный текст — на плиточной вёрстке (несколько карточек лотов рядом) это может склеить цену/площадь соседних юнитов в один поток без чёткой привязки к конкретному лоту. Неверная цена в карточке Avito — прямой юридический риск (ст. 14.3 КоАП РФ, штраф для юрлица 100 000–500 000 ₽). На JS-рендеренных сайтах застройщиков Exa получает пустой результат.

Для окончательной проверки конкретной цены/юнита перед публикацией — `mcp__firecrawl__firecrawl_scrape` c `formats: ["extract", "screenshot"]` и JSON-схемой полей (`rooms`/`area_sqm`/`price_rub` и т.п.), не текстовый `web_fetch_exa`. Схема возвращает каждый юнит отдельным объектом — цена и площадь не могут перепутаться между соседними карточками, и рендерит JS. Скриншот в том же вызове — для визуальной сверки владелицей/CMO, не только доверия к тексту.

Firecrawl настроен глобально (`~/.claude.json`, тем же способом, что и Exa) — не в `.mcp.json` этого репозитория, отдельно подключать здесь не нужно.

Exa остаётся инструментом по умолчанию для обычного поиска/чтения — Firecrawl подключается точечно, на шаге проверки конкретной цены/юнита перед публикацией, не заменяет Exa везде.
