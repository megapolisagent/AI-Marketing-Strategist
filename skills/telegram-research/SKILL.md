# Telegram Research

## Когда нанимают

Нужен контент из русскоязычных Telegram-каналов — реальные жалобы клиентов, посты брокеров/конкурентов, рыночная аналитика, которая публикуется в Telegram раньше или вместо обычного веба.

## Когда нельзя использовать

- Нужны закрытые каналы (по инвайту) или переписки в привязанных чатах обсуждения под постами — этот Skill их не откроет. Это отдельная задача (Telegram Bot API/MTProto через клиент вроде Telethon), не реализовано, инструментов для неё в этой среде нет.
- Тема хорошо освещена в открытом вебе — обычный WebSearch/WebFetch достаточен, не усложнять без нужды.
- Нужен систематический мониторинг многих каналов на постоянной основе — разовое чтение ленты сюда не масштабируется.

## Метод

### 1. Найти канал
WebSearch по теме + сегменту (`"<тема>" telegram канал`, `site:t.me <тема>`) или агрегаторы (tgstat.ru, telemetr.me). **Не угадывать хэндл по названию бренда** — подтверждено на тесте: 2 из 3 хэндлов, угаданных по памяти из известных брендов, оказались пустыми или несуществующими каналами. Хэндл должен прийти из реального поискового результата, не из догадки.

### 2. Проверить канал и достать сырой HTML — не через WebFetch
```bash
curl -s -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36" "https://t.me/s/<handle>" -o /tmp_канал.html
```
**Почему не WebFetch:** WebFetch пропускает страницу через суммаризирующую модель — не даёт дословный текст, и на тесте один раз исказил содержание (приписал каналу характеристику "офис для отмывания денег", которой не было в исходном посте — вероятная галлюцинация поисковой выжимки, выданная за факт). Для точных цитат единственный проверенный рабочий путь — сырой `curl` + `Grep`/`Read` по HTML.

**Проверка, что канал реальный и открытый:**
- Размер страницы заметно больше пустой заглушки (пустой/несуществующий канал — часто ~25KB и меньше, почти без постов).
- В `<link rel="canonical">` не должно быть `?before=` с маленьким числом сразу на первой странице без реальных постов — это признак пустого/мёртвого хэндла.
- Хэндл может вместо ленты канала отдать generic-страницу "Contact @handle" — значит это не канал, а личный аккаунт/бот, контента нет.

### 3. Прочитать содержимое
`Grep`/`Read` по скачанному HTML. Настоящие посты несут дату, счётчик просмотров и (часто) реакции рядом с текстом — это сигнал подлинности, отличающий реальный пост от шаблонного элемента страницы.

### 4. Пагинация вглубь ленты
`https://t.me/s/<handle>?before=<id_самого_старого_поста_на_текущей_странице>` — повторить curl с новым URL.

### 5. Конкретный пост по прямой ссылке
Тот же принцип: `curl` на `https://t.me/s/<handle>/<номер>`, не WebFetch, если нужна точная цитата, а не пересказ.

### 6. Разметить достоверность
- **ЗНАЮ** — дословная цитата из сырого HTML, с датой/просмотрами/реакциями как подтверждением.
- **ПРЕДПОЛАГАЮ** — вывод или перенос находки на ваш сегмент/аудиторию, не сама цитата.
- **Явно отделять голос индустрии от голоса клиента.** Открытые Telegram-каналы в этой нише — почти всегда broker/агентские/девелоперские broadcast-каналы (индустрия говорит покупателю или о покупателе), не сами покупатели. Если из канала взят вывод о том, что «чувствует клиент» — это интерпретация поверх чужого текста, помечать как ПРЕДПОЛАГАЮ, не выдавать за прямую цитату клиента.

### 7. Зафиксировать
В knowledge-файл — с прямой ссылкой на источник (`t.me/канал/номер`) и датой, не как общий пересказ «в Telegram пишут, что…».

## Self Check

Если в записи нет точной цитаты со ссылкой/датой, а есть только пересказ своими словами — это не ЗНАЮ, а как минимум ПРЕДПОЛАГАЮ, разметить соответственно.

## Что получает следующий потребитель

Не общий вывод «в Telegram обсуждают X», а конкретные дословные цитаты со ссылкой и датой, размеченные ЗНАЮ/ПРЕДПОЛАГАЮ и с пометкой «голос индустрии» vs «голос клиента» — готовые вставляться в knowledge-файл без дополнительной проверки.

## Известные границы (честно, не молчать)

- Закрытые каналы, чаты обсуждения под постами, систематический мониторинг многих каналов одновременно — не покрыто. Нужен настоящий Telegram API (Bot API или MTProto-клиент) — не реализовано в этой среде.
- Метод найден и провалидирован на открытых broadcast-каналах о недвижимости (RED/GREEN тест 2026-08-19, `AI Marketing Strategist`) — для другой тематики список хэндлов и поисковых запросов свой, сам метод (curl вместо WebFetch, проверка хэндла, разметка ЗНАЮ/ПРЕДПОЛАГАЮ) переносится без изменений.
